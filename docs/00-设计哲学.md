# 第 00 章 · 设计哲学：为什么会有 AI Agent

> 本章不教你写一行代码，但它决定了你后面 11 章会不会白学。
> 本章你需要记住的就一件事：**Agent 不是"更聪明的聊天机器人"，而是"让模型在循环里自主调用工具、直到完成任务"的一套工程范式。**

---

## 00.1 从一个让你困惑的现象说起

2022 年底 ChatGPT 爆火。你问它一句，它答一句。你很满意，直到你让它做一件"真正的事"：

> 「帮我查一下北京今天的天气，如果下雨就提醒我出门带伞。」

ChatGPT 会说：抱歉，我无法获取实时天气，我的知识截止到 2023 年。

你心里大概会想：**它连"查天气"这种小事都做不了，算什么智能？**

但换一个产品，你问同样的话，它却真的打开了天气网站、读了结果、判断了"下雨"，最后给你一句「今天北京有小雨，出门记得带伞」。

区别不在"模型更聪明"——它们背后可能是**同一个模型**。区别在于：后者给模型装上了"手"和"眼睛"，让它能**反复行动**，而不只是"回答一次"。

这个"装上手脚、放进循环"的东西，就是 **AI Agent（智能体）**。

> 一句话记住它：模型只负责"想"，Agent 负责"让模型在循环里想一步、动一步"。

---

## 00.2 Agent 到底是怎么出现的

要理解 Agent，先看清大模型的**两个先天缺陷**，Agent 就是为了补这两个缺陷而被发明出来的。

### 缺陷一：模型是"无状态"的

很多人以为模型"记得"你们之前的对话。这是误解。

模型的每一次调用，都是**独立的一次函数调用**：你给它什么输入，它返回什么输出，调用结束它就"失忆"了。上一轮说过的话，它一个字都不记得。

那为什么 ChatGPT 能"记得"你刚才说的？因为**应用层**（也就是写 ChatGPT 的人）把你之前的对话，和你的新问题一起，**拼成一个新的输入**重新喂给了模型。

```text
第 1 次调用：输入 = "1+1 等于几？"          → 输出 = "2"
第 2 次调用：输入 = "1+1 等于几？\n答：2\n那 2+2 呢？" → 输出 = "4"
```

看到了吗？第二次调用时，你的第一轮问答被**手动拼了回来**。模型本身什么都没记住。

> 一句话记住它：模型是无状态的，所谓"记忆"是应用层每次把历史对话重新拼进输入。这个"拼输入"的动作，就是 Agent 最核心的职责之一。

### 缺陷二：模型只能"输出文本"

模型只能吐出文字，它**不能上网、不能读文件、不能执行代码、不能查数据库**。它甚至连"现在几点"都不知道。

那怎么让它"查天气"？答案是：让模型**输出一个"我想调用某个工具"的指令**（文本），然后由**你的代码**去真正执行这个工具，把工具的结果再喂回给模型。

```text
你：查北京天气
模型（文本输出）：我想调用 get_weather(city="北京")   ← 这只是一段"想法的文字"
你的代码：真正去执行 get_weather("北京")，得到 "小雨，22℃"   ← 真正干活的是你
模型（再输入）：get_weather 返回 "小雨，22℃"，请回答用户  → 输出 "今天有小雨…"
```

整个过程，模型始终**只在"想"和"说"**，真正"动手"的是你写的代码。这就是 Agent 的本质：**模型负责决策，代码负责执行**。

> 一句话记住它：模型不能行动，它只能"表达想行动的意愿"；真正行动的是你的代码。Agent = 模型（大脑）+ 工具（手脚）+ 循环（让它反复动）。

## 00.3 一段关键历史（你要知道的名词和年份）

Agent 不是 2024 年突然蹦出来的，它有一条清晰的演进线。面试和聊天里提到这些，你会显得懂行：

| 时间 | 事件 | 对 Agent 的意义 |
|---|---|---|
| 2022-10 | ReAct 论文（Yao 等人） | 首次提出「**推理（Reason）+ 行动（Act）**」交替循环，是今天 agent loop 的雏形 |
| 2023-03 | AutoGPT 开源爆火 | 把「自主循环执行目标」推向大众，也暴露了 agent 失控、烧钱、跑偏的问题 |
| 2023-06 | OpenAI 推出 **function calling** | 模型能输出**结构化的工具调用参数**，这是工具调用的工业级落地 |
| 2023-11 | OpenAI 发布 **Assistants API** | 官方把"线程/工具/检索"打包，Agent 从"自己造轮子"变成"用现成的" |
| 2024 起 | LangChain / LangGraph 等框架成熟 | 把 agent 的状态管理、循环控制、工具编排沉淀为框架 |

你不需要背这些，但要记住一个趋势判断：**Agent 正从"手写一个 while 循环"进化成"有框架、有状态、可观测的工程**。

> 一句话记住它：ReAct 给了"循环"，function calling 给了"手脚"，框架给了"工程化"。

## 00.4 Agent 的官方定义（翻译成人话）

学界和业界对 Agent 没有一个唯一的权威定义，但几份最有影响力的描述指向同一个方向。我们把它们翻译成人话：

**定义一（Lilian Weng 的经典博客《LLM Powered Autonomous Agents》，2023-06）：**

> Agent = LLM（大脑）+ 规划（Planning）+ 记忆（Memory）+ 工具使用（Tool Use）。

人话：模型负责思考；"规划"让它拆解任务、一步步来；"记忆"让它不健忘；"工具"让它能动手。四块缺一不可。

**定义二（Anthropic《Building Effective Agents》，2024-12）：**

> Agent 是"模型在循环中自主决定和控制自己的**工具调用和流程**"的系统；而"工作流"（workflow）是"通过**预定义代码路径**编排 LLM 和工具"的系统。

这句话极其重要，它划清了一条**很多人搞混的界线**，请看下一节。

> 一句话记住它：Agent 的核心四件套是「大脑 + 规划 + 记忆 + 工具」；而"模型自主决定流程"是 Agent 和普通工作流的本质区别。

## 00.5 核心哲学：三条，每条都值回票价

### 哲学一：**Agent 的边界是"模型是否自主决定流程"**

Anthropic 在《Building Effective Agents》里有一句反直觉的忠告：

> **能不用 Agent，就尽量不用 Agent。用最简单的"工作流"就能解决的问题，不要上 Agent。**

为什么？因为"自主"是要付出代价的：更贵、更慢、更容易跑偏、更难调试。

看两个对比：

```text
【工作流（Workflow）】——流程是"写死的"
用户输入 → 固定调用「分类」→ 固定调用「翻译」→ 固定输出
每一步走哪条路，是程序员在代码里写死的，模型没有"选择权"。

【Agent】——流程是"模型现决定的"
用户输入 → 模型自己判断"该调哪个工具？调几次？下一步干什么？"
模型拥有对流程的"自主控制权"。
```

判断标准一句话：**如果你的流程可以预先画成一张确定性的流程图，那它就该用工作流实现，而不是 Agent。**

> 一句话记住它：Agent 的"智能"来自"模型自主决定下一步"，但这恰好也是最贵、最难控制的地方。能用工作流就别用 Agent。

### 哲学二：**上下文窗口是 Agent 的"内存条"，是硬约束**

模型每次调用能"看见"的输入有上限，这个上限叫**上下文窗口（context window）**。Agent 要反复循环，每一轮都要把历史对话、工具结果、系统提示全部塞进这个窗口。

后果很现实：

- 循环次数越多，窗口越满，越到后面模型越"健忘"（因为早先的内容被挤出去了）。
- 工具返回的"巨型结果"（比如一个 5000 行的文件）会瞬间吃掉窗口。

所以 Agent 工程有个永恒的主题：**如何用有限的窗口，装下完成任务所需的最关键信息**。这就是后面"记忆管理""上下文压缩""检索"这些章节存在的根本原因。

> 一句话记住它：上下文窗口是 Agent 的第一物理约束，所有"记忆""压缩""检索"技巧，本质都是在跟这个窗口抢空间。

### 哲学三：**Agent 是"不可靠的可靠系统"**

一个函数 `add(1, 2)` 返回 3，跑一百万次都是 3。但一个 Agent 处理"总结这篇文章"，跑一百次可能给你一百个略有不同的总结——**因为模型是概率性的，不是确定性的**。

这意味着 Agent 工程要做一件传统软件工程很少做的事：**为"不确定性"做设计**。具体包括：

- **重试**：模型某次调用出错了，重来一次。
- **校验**：模型声称"完成了"，你要验证它真的完成了（比如真的调用了工具、结果真的符合格式）。
- **兜底**：模型跑偏了、死循环了，你要有"强制停止"和"降级到人工"的机制。

> 一句话记住它：Agent 的底层是概率模型，所以 Agent 的代码里必须到处都是"重试、校验、兜底"，这是它和普通 CRUD 最大的工程差异。

## 00.6 反面清单：Agent 明确不擅长什么

讲了那么多"能做什么"，你必须同时知道它**不能做什么**，否则会拿它去撞南墙：

| Agent 不擅长 / 做不到 | 原因 |
|---|---|
| **保证 100% 正确** | 模型有幻觉，会一本正经地编造 |
| **确定性、可复现的任务** | 同样的输入可能得到不同输出 |
| **高频、低延迟的调用** | 每次循环都要走一次模型，又贵又慢 |
| **需要精确算术 / 复杂逻辑** | 模型不擅长精确计算，得靠"调用计算器/代码"工具来补 |
| **长时间完全无人值守** | 会跑偏、会烧钱、会死循环，需要监控和人工兜底 |
| **替代传统软件工程** | 该用数据库、该写 SQL、该写确定性算法的地方，别硬塞给模型 |

一个健康的认知是：**Agent 是"给传统软件加一个会思考的组件"，不是"用模型重写一切"**。

> 一句话记住它：Agent 是"会思考的胶水"，把确定性的代码和概率性的判断粘在一起，而不是取代确定性本身。

## 00.7 你即将学到的，是一张完整地图

后面 11 章，就是把这个"哲学"落成"能跑的代码"的过程。先给你一张全景图，心里有数：

```
        ┌─────────────────────────────────────────────┐
        │               Agent Loop（核心循环）           │
        │                                             │
        │   ┌──────┐    ┌──────────┐    ┌─────────┐   │
        │   │ 记忆  │ ──→│ 调用模型  │ ──→│ 判断输出 │   │
        │   │(状态) │    │ (大脑)   │    │ 是文字/  │   │
        │   └──────┘    └──────────┘    │ 工具调用? │   │
        │        ↑                        └────┬────┘   │
        │        │              ┌───────────────┘       │
        │        │              ↓                        │
        │        │     ┌──────────────┐                  │
        │        └─────│ 执行工具/返回  │                  │
        │              └──────────────┘                  │
        └─────────────────────────────────────────────┘
```

- **第 01 章**：心智模型——Agent 的"大脑、记忆、工具、循环"四个零件到底长什么样。
- **第 02~07 章**：逐个零件深入——提示词、工具调用、记忆管理、多步推理、结构化输出、安全与护栏。
- **第 08 章**：工程化——把"能跑"变成"可维护、可观测、可测试"。
- **第 09 章**：实战——从零搭一个完整的、分层的 Agent 应用。
- **第 10 章**：分级测试题，检验你到底会没会。
- **第 11 章**：面试速查表，把这套东西变成你的面试弹药。

## 00.8 本章小结

- 模型是**无状态**的，所谓"记忆"是应用层每次把历史拼回输入。
- 模型**不能行动**，只能"表达想行动的意愿"，真正干活的是你的代码。
- Agent = **大脑（模型）+ 记忆 + 工具 + 循环**，四件套。
- Agent 和"工作流"的本质区别是：**流程是否由模型自主决定**。
- **能不用 Agent 就不用**，能画成确定性流程图的任务，用工作流更稳更省。
- **上下文窗口**是 Agent 的第一物理约束。
- Agent 是**概率系统**，代码里必须到处是"重试、校验、兜底"。

## 00.9 动手练习（思考题，不写代码）

1. 下面哪一个是 Agent，哪一个是工作流？为什么？
   - (a) 一个客服机器人：固定流程「识别问题类型 → 查知识库 → 返回答案」。
   - (b) 一个「帮用户订机票」的助手：模型自己决定"先查航班，还是先问日期，还是查完航班后提醒用户带身份证"。

   <details><summary>参考答案</summary>
   (a) 是工作流：流程固定、每一步走哪条路是写死的，模型没有自主权。
   (b) 是 Agent：模型自主决定"下一步干什么、调哪个工具、调几次"。判断标准就是"流程是否由模型决定"。
   </details>

2. 为什么说"模型的记忆"是假的？真正的记忆放在哪里？

   <details><summary>参考答案</summary>
   模型每次调用都是无状态的独立计算，它自身不保存任何跨调用的信息。真正的记忆存放在**你的应用代码里**（比如一个 messages 数组、一个数据库），每次调用前由你的代码把记忆拼进输入。
   </details>

3. 一个 Agent 死循环了，一直调用同一个工具，最可能的原因是什么？你该怎么防？

   <details><summary>参考答案</summary>
   原因：模型没意识到"已经拿到了足够信息"，或者工具结果格式让它困惑，导致它反复调用同一个工具。防法：设置**最大循环次数**（max iterations），超限强制停止；每次循环检查是否重复调用同一工具；必要时降级到"人工介入"。
   </details>
